# Frozen TPC-H sf=0.1 answers

`tpch_sf01.json` contains nine complete result sets for all ten answerable cases;
explicit and default customer-region questions share one result. Contracts,
stable case IDs, grouping keys, and accepted column aliases live in
`eval/test_suite.py`. No fixture is generated by the runtime agent or its reviewer.

`reference_queries.json` contains independently authored base-fact SQL and eight
aggregate equivalents. Each query includes a canonical contract identifying the
metric-definition file/sections, formula, exclusions, grain, intended agent layer,
time basis/filter, and layer authority. The supplier result has no aggregate equivalent. Revenue
uses discounted line amounts, order volume uses distinct orders, and AOV divides
total revenue by distinct orders at the requested grain. Trends use order date;
geography follows the respective customer or supplier path. Aggregate checks use
the application's existing demo setup, while reference answers use base facts.

`provenance.json` records the repository revision, hashes of context/reference SQL
and demo setup plus `eval/test_suite.py` (with normalized newlines), engine/extension
version, scale, status distribution, checks, and
review status. Owner review of the reference SQL and tolerances remains pending;
generation and automated cross-checks do not substitute for that review.

Counts compare exactly. Revenue and AOV use a fixed absolute tolerance of `0.005`
and zero relative tolerance. This accepts correctly rounded two-decimal answers,
including the half-cent boundary, without increasing the allowance for large
values. Values are not rounded before comparison. Full-precision goldens remain
unchanged; JSON numeric encoding accommodates DuckDB decimal/float outputs.

Comparison is independent of row/column order. Date keys accept ISO dates, Python
dates, and timezone-free midnight timestamps. Year/month keys accept integral
numbers and digit strings (including `01`); metric values never accept strings or
booleans. Counts may use integral floats. Explicit aliases match case-insensitively and must map one-to-one; missing,
ambiguous, or duplicate columns fail. Extra output columns are allowed by default;
`result.exact_schema: True` opts a case into rejecting them. Narrow key aliases
include date, year, month, region, and nation only in the corresponding contracts.
No fuzzy matching or value-based column selection is used. Extra/missing rows, duplicate keys,
nulls, and nonfinite values fail. Expected nulls/empty results are deliberately
unsupported by these ten nonempty contracts.

The evaluator-local layer check resolves SQLGlot scopes to physical demo tables.
Comments, literals, aliases, shadowing CTEs, and unused CTEs cannot supply a layer.
Unknown sources, multiple statements, parsing failures, and aggregate/fact mixtures
fail the required layer check. This is a conservative table-use check, not a proof
of SQL lineage, join correctness, or whether every referenced source contributes
to a metric. Application logging retains its existing layer detector.

Out-of-range cases require the explicit flag, no data (even an empty DataFrame
fails), false execution/validation flags, and the existing nonempty
`OUT_OF_RANGE:` response in the SQL field. Terminal state cannot prove that no
execution happened; runtime execution ownership is outside this batch.

Run scorer, provenance, and available reference tests:

```powershell
python -m pytest tests/test_eval_scoring.py tests/test_eval_golden.py -q
```

Reference tests automatically run when the local TPC-H extension loads. They
skip with an explicit availability reason when it cannot load; setup and reference
query errors after that probe fail normally. Tests never rewrite fixtures:

```powershell
python -m pytest tests/test_eval_golden.py -q
python -m eval.golden --check
```

Only an intentional generation operation rewrites fixtures/provenance:

```powershell
python -m eval.golden --write
```

Review the resulting diff and provenance before accepting regenerated answers.
`--check` verifies full reference answers, aggregate equivalents, and recorded
source/fixture hashes. A different DuckDB version is printed; passing comparisons
show compatibility with these fixtures, not identical generator provenance.

Live evaluation (`python -m eval.run_eval`) uses committed fixtures, requires
OpenAI credentials, incurs API usage, and logs through the unchanged shared runner.
Fixture configuration is validated before any live execution. Scorer failures
are reported separately from the runtime's own verification status.

The generated orders have statuses F, O, and P, with no C orders. These results
cannot verify cancellation-filter enforcement. Reference SQL includes the global
`o_orderstatus <> 'C'` rule even though the bundled supplier SQL example omits it.
No synthetic cancellation dataset or runtime context change is included here.
